# MIP-X56: Improve OEV Fee-Split Accuracy

## Summary

This proposal refreshes Moonwell’s Chainlink OEV oracle wrappers on Base and
Optimism to make OEV liquidation fee-splitting more accurate and consistent.

Today, Moonwell uses OEV-aware oracle wrappers to help split value from certain
liquidations between the protocol and liquidators. The configured split is
currently 30% to the liquidator and 70% to the protocol. This proposal updates
the oracle wrapper logic so that this split is calculated using consistent,
fresh price references on both sides of the liquidation.

The proposal does not change user-facing market behavior, interest rates,
collateral factors, liquidation thresholds, or the underlying assets supported
by Moonwell. It is a technical improvement designed to ensure the protocol’s OEV
fee policy is executed as intended.

## Background

Oracle Extractable Value, or OEV, refers to value that can arise when
liquidations depend on oracle price updates. Moonwell’s OEV system is designed
to allow liquidators to update prices early and perform liquidations while
sharing the realized value with the protocol.

The current configured fee split is:

- 30% of realized OEV value to the liquidator
- 70% of realized OEV value to the protocol

This split is determined by comparing the value of the collateral side of a
liquidation against the value of the loan side. For that calculation to work
correctly, both prices need to be read from sources with the same freshness
assumptions.

While user funds and protocol principal are not at risk, the current mismatch
could cause the realized fee split to differ from the intended 70/30 policy in
certain cases.

## Proposal

This proposal updates the OEV oracle wrapper system so that the fee-split
calculation uses consistent price references.

Specifically, this proposal will:

1. Refresh every live Core `ChainlinkOEVWrapper` listed in Moonwell’s Chainlink
   oracle configurations on Base and Optimism.

2. Preserve each existing wrapper’s configuration, including:

   - Price feed
   - Chainlink oracle
   - Fee recipient
   - Owner
   - Liquidator fee basis points
   - Maximum round delay
   - Maximum decrements

3. Replace the current wrapper logic with improved loan-feed resolution logic,
   so the loan-side price resolves down to the raw Chainlink aggregator before
   being used in the OEV fee-split calculation.

4. On Base, upgrade the `ChainlinkOEVMorphoWrapper` implementation to:

   - Match the Core wrapper’s round-data validation standards
   - Use Morpho’s canonical per-market loan feed
   - Add a per-proxy market allowlist so the OEV liquidation path can only be
     used with Moonwell-approved canonical markets

5. Archive the existing wrapper addresses under deprecated names and register
   the refreshed wrappers under the canonical OEV wrapper names.

## Rationale

This proposal is important because Moonwell’s OEV system should execute the
DAO’s intended economic policy precisely.

The protocol has already chosen a 70/30 split for OEV liquidations, with 70% of
realized value going to the protocol and 30% going to the liquidator. The
purpose of this proposal is not to change that policy. Instead, it ensures the
existing policy is applied correctly across all supported loan-symbol
configurations.

## Voting Options

- **For:** Refresh the Chainlink OEV wrappers on Base and Optimism, upgrade the
  Base Morpho OEV wrapper implementation, and improve OEV fee-split accuracy.
- **Against:** Do not refresh the Chainlink OEV wrappers or upgrade the Base
  Morpho OEV wrapper implementation.
- **Abstain:** Participate in governance without voting for or against the
  proposal.
