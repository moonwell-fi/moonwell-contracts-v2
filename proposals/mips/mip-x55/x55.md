# MIP-X56: Improve OEV Fee-Split Accuracy (Full-Coverage Wrapper Refresh)

## Summary

Refreshes every Core `ChainlinkOEVWrapper` enumerated in
`ChainlinkOracleConfigs._oracleConfigs` on Base and Optimism so that the
liquidator/protocol fee split during OEV liquidations is computed against a
consistent, fresh price reference on both sides of the trade. On Base, the
`ChainlinkOEVMorphoWrapper` proxy implementation is also upgraded to bring the
Morpho-side wrapper to parity with the Core wrapper's round-data validation and
to introduce a per-proxy market allowlist for the OEV path.

Each refreshed wrapper preserves the existing wrapper's full configuration read
live from on-chain state (`priceFeed`, `chainlinkOracle`, `feeRecipient`,
`owner`, `liquidatorFeeBps`, `maxRoundDelay`, `maxDecrements`), so the only
observable change post-upgrade is the improved loan-feed resolution logic.

## Motivation

OEV liquidations split realized value between the protocol and the liquidator
according to `liquidatorFeeBps` (currently 3000 bps — 30% to the liquidator, 70%
to the protocol). That split is computed from
`collateralPrice * collateralAmount` versus `loanPrice * loanAmount`, so it
relies on both prices being read from references with the same freshness
characteristics.

In the current wrappers, the collateral side reads its raw Chainlink aggregator
directly via `priceFeed`, while the loan side resolves through
`ChainlinkOracle.getFeed(symbol)`. For loan symbols whose registry entry is
itself an OEV wrapper, the loan price returned is that wrapper's _delayed_
(OEV-protected) value, while the collateral price is the fresh raw aggregator
reading. This asymmetric freshness can cause the realized split to deviate from
the configured 70/30: a sophisticated liquidator could time interactions so that
the loan-side delay works in their favor, capturing a larger share of OEV value
than the configured policy permits.

This proposal makes the split math symmetric. Both sides now resolve down to the
same kind of fresh, raw Chainlink reading, so the executed split always matches
`liquidatorFeeBps`. No funds are at risk and the protocol's principal is
unaffected — the change tightens the accuracy of the fee-split policy under all
loan-symbol configurations, including future symbols whose registry entry
happens to be wrapped.

## What the change does

The refreshed Core wrapper resolves the loan-side feed down to its raw Chainlink
aggregator before reading `latestRoundData()` (single-hop, non-recursive,
defensive against feeds that do not expose `priceFeed()`).

The Morpho wrapper upgrade brings its loan-side validation to parity with the
Core wrapper (`updatedAt != 0` and `answeredInRound >= roundId` are now
enforced), reads the loan price from `MarketParams.oracle.QUOTE_FEED_1` (the
Morpho-canonical per-market loan feed) rather than re-deriving it from the Core
registry, and introduces a per-proxy market allowlist so the OEV path is
exercised only against the canonical Moonwell-curated market for each oracle
proxy, not arbitrary permissionless markets that happen to reference the same
proxy.

## Impact

No funds at risk. No change to user-visible market behavior, interest rates,
collateral factors, or liquidation thresholds. The proposal tightens the
accuracy of the OEV liquidator/protocol fee split so that the executed split
always matches the configured `liquidatorFeeBps` (70/30 today), regardless of
whether a loan symbol's registry entry is a raw Chainlink aggregator or another
OEV wrapper.

## Actions

### Base

For every `oracleName` enumerated in `ChainlinkOracleConfigs._oracleConfigs`
(Base) that resolves to a live OEV wrapper:

- Archive the existing wrapper address under
  `<oracleName>_OEV_WRAPPER_DEPRECATED_V3` (the X43-era wrapper being retired).
- Deploy a refreshed `ChainlinkOEVWrapper` mirroring the existing wrapper's
  on-chain parameters exactly and register it under the canonical
  `<oracleName>_OEV_WRAPPER`.
- `ChainlinkOracle.setFeed(symbol, newWrapper)` for every symbol mapped to that
  `oracleName` (e.g. `CHAINLINK_USDC_USD` covers both `USDC` and `USDbC`).

Covered Base feeds: `DAI_ORACLE`, `CHAINLINK_USDC_USD`, `CHAINLINK_ETH_USD`,
`CHAINLINK_AERO_ORACLE`, `CHAINLINK_BTC_USD`, `CHAINLINK_EURC_USD`,
`CHAINLINK_WELL_USD`, `CHAINLINK_USDS_USD`, `CHAINLINK_TBTC_USD`,
`CHAINLINK_VIRTUAL_USD`, `CHAINLINK_MORPHO_USD`, `CHAINLINK_cbXRP_USD`,
`CHAINLINK_MAMO_USD`, `CHAINLINK_VVV_USD`.

Composite-wrapped feeds (`_compositeOracleConfigs`) are intentionally left
untouched.

Additionally, upgrade ALL three `ChainlinkOEVMorphoWrapper` proxies to a single
shared new implementation (`CHAINLINK_OEV_MORPHO_WRAPPER_IMPL_V2`). The new
implementation gates `updatePriceEarlyAndLiquidate` behind a per-proxy market
allowlist, ensuring the OEV split policy is exercised only against the canonical
Moonwell-curated market for each oracle proxy. Each proxy is upgraded via plain
`proxyAdmin.upgrade(proxy, newImpl)` followed by
`proxy.setApprovedMarket(canonicalId, true)` queued in the same governance
proposal. Both actions execute atomically within one proposal execution, so
there is no window in which the gate is live but the canonical market is
unapproved. `setApprovedMarket` is `onlyOwner`-gated (owner =
TEMPORAL_GOVERNOR), unfront-runnable. Proxies upgraded and seeded:

- `CHAINLINK_WELL_USD_ORACLE_PROXY` — seeded with WELL/USDC market
- `CHAINLINK_MAMO_USD_ORACLE_PROXY` — seeded with MAMO/USDC market
- `CHAINLINK_stkWELL_USD_ORACLE_PROXY` — seeded with stkWELL/USDC market

Canonical market params per proxy mirror the live integration test
(`testUpdatePriceEarlyAndLiquidate_*` in
`ChainlinkOEVMorphoWrapperIntegration.t.sol`). All three borrow USDC against
their respective collateral asset using `MORPHO_ADAPTIVE_CURVE_IRM`. lltv =
0.625e18 (WELL, stkWELL) / 0.385e18 (MAMO).

### Optimism

For every `oracleName` enumerated in `ChainlinkOracleConfigs._oracleConfigs`
(Optimism) that resolves to a live OEV wrapper:

- Archive the existing wrapper address under
  `<oracleName>_OEV_WRAPPER_DEPRECATED_V3` (the X43-era wrapper being retired).
- Deploy a refreshed `ChainlinkOEVWrapper` mirroring the existing wrapper's
  on-chain parameters exactly and register it under the canonical
  `<oracleName>_OEV_WRAPPER`.
- `ChainlinkOracle.setFeed(symbol, newWrapper)` for every symbol mapped to that
  `oracleName` (e.g. `CHAINLINK_USDT_USD` covers both `USDT` and `USD₮0`).

Covered Optimism feeds: `CHAINLINK_USDC_USD`, `CHAINLINK_USDT_USD`,
`CHAINLINK_DAI_USD`, `CHAINLINK_ETH_USD`, `CHAINLINK_WBTC_USD`,
`CHAINLINK_OP_USD`, `CHAINLINK_VELO_USD`.

## Parameters preserved

Per-wrapper parameters are read from on-chain state at deploy time and mirrored
on the refreshed wrapper. At the time of writing every wrapper on Base and
Optimism is configured with `liquidatorFeeBps=3000`, `maxRoundDelay=10`,
`maxDecrements=10` (set by MIP-X43), but the proposal does not assume this —
each new wrapper inherits whatever parameters its predecessor held.
