# MIP-X55: Accept xWELL Bridged from Ethereum Mainnet

## Summary

This proposal extends the Moonwell `xWELL` bridge mesh to include Ethereum
mainnet. It adds the Ethereum `WormholeBridgeAdapter` as a trusted sender and
outbound target on each of the existing chains' adapters (Moonbeam, Base, and
Optimism) so they can accept inbound `xWELL` bridged from mainnet and route
outbound transfers back to it.

The proposal is executed by the **Moonbeam `MultichainGovernor`**:

- Moonbeam actions run directly.
- Base and Optimism actions are delivered to each chain's `TemporalGovernor` via
  Wormhole.

The reciprocal Ethereum-side wiring (`addTrustedSenders` + `setTargetAddresses`
on the Ethereum adapter) plus the deployer → multisig ownership transfer for
both `xWELL` and the Ethereum `WormholeBridgeAdapter` is **not** in this
proposal. It is handled by `script/EnableEthereumXWellBridging.s.sol`, broadcast
by `MOONWELL_DEPLOYER` before MIP-X56.

## Motivation

`xWELL` is deployed on Ethereum mainnet:

- `xWELL_PROXY`: `0xA88594D404727625A9437C3f886C7643872296AE`
- `WORMHOLE_BRIDGE_ADAPTER_PROXY`: `0x734AbBCe07679C9A6B4Fe3bC16325e028fA6DbB7`

The existing chains' adapters do not yet recognize the Ethereum adapter, so any
VAA emitted from Ethereum to bridge `xWELL` to Moonbeam, Base, or Optimism would
be rejected, and outbound `bridge()` calls to Ethereum from those chains would
revert with no target configured.

MIP-X56 will migrate governance to Ethereum and rely on `xWELL` voting power
sourced from all four chains, so the bridge mesh must be live first.

## Specification

For each existing chain (Moonbeam, Base, Optimism), the proposal sends two calls
to the local `WORMHOLE_BRIDGE_ADAPTER_PROXY`:

1. `addTrustedSenders((uint16,address)[])` with the Ethereum peer — whitelists
   inbound VAAs from the Ethereum adapter.
2. `setTargetAddresses((uint16,address)[])` with the Ethereum peer — sets the
   outbound destination address for Wormhole chain id `2`.

### Peer used by every chain

| Wormhole Chain ID | Ethereum Adapter Address                     |
| ----------------- | -------------------------------------------- |
| 2                 | `0x734AbBCe07679C9A6B4Fe3bC16325e028fA6DbB7` |

(All `WormholeBridgeAdapter` deployments share the same CREATE2 address.)

### Action breakdown

| Chain    | Executor                      | Action                           |
| -------- | ----------------------------- | -------------------------------- |
| Moonbeam | `MultichainGovernor` (direct) | `addTrustedSenders([Ethereum])`  |
| Moonbeam | `MultichainGovernor` (direct) | `setTargetAddresses([Ethereum])` |
| Base     | `TemporalGovernor` (Wormhole) | `addTrustedSenders([Ethereum])`  |
| Base     | `TemporalGovernor` (Wormhole) | `setTargetAddresses([Ethereum])` |
| Optimism | `TemporalGovernor` (Wormhole) | `addTrustedSenders([Ethereum])`  |
| Optimism | `TemporalGovernor` (Wormhole) | `setTargetAddresses([Ethereum])` |

## Out-of-band Ethereum setup

Before this proposal is executed, `MOONWELL_DEPLOYER`
(`0xdDbf679d6332d9E5b409865b9671d1927255B52A`) runs:

```sh
forge script script/EnableEthereumXWellBridging.s.sol:EnableEthereumXWellBridging \
  --rpc-url ethereum --broadcast --private-key $DEPLOYER_PRIVATE_KEY
```

In one broadcast the script:

1. Calls `addTrustedSenders` and `setTargetAddresses` on the Ethereum
   `WORMHOLE_BRIDGE_ADAPTER_PROXY` for the Moonbeam, Base, and Optimism peers.
2. Calls `transferOwnership(FOUNDATION_MULTISIG)` on the Ethereum
   `WORMHOLE_BRIDGE_ADAPTER_PROXY` and on `xWELL_PROXY` (Ownable2Step).

The Foundation multisig (`0x74Cbb1E8B68dDD13B28684ECA202a351afD45EAa`) then
submits two Safe transactions calling `acceptOwnership()` on each proxy to
complete the handover.

> **Verify** that `0x74Cbb1E8B68dDD13B28684ECA202a351afD45EAa` is the canonical
> Moonwell Foundation Safe on Ethereum mainnet (matches the address registered
> on Base) before broadcasting. If a different Safe is desired, update
> `chains/1.json#FOUNDATION_MULTISIG` first.

## Execution

```sh
forge script proposals/mips/mip-x55/mip-x55.sol:mipx55 -vvv
```

With `DO_BUILD=true DO_RUN=true DO_VALIDATE=true`, the script queues all six
actions in `MultichainGovernor`, simulates governance execution and Wormhole
delivery to Base/Optimism, and validates that each remote adapter has the
Ethereum peer in `trustedSenders` and `targetAddress[2]`.

## Security

- `addTrustedSenders` and `setTargetAddresses` are `onlyOwner`-guarded; the
  owner on Moonbeam/Base/Optimism is the local governance entity, which is the
  expected caller via this proposal.
- `addTrustedSenders` uses `EnumerableSet.add`, which reverts on duplicates —
  this proposal is first-time wiring for the Ethereum peer; safe re-runs would
  need `removeTrustedSenders` first.
- No upgrades, no token movement, no rate-limit changes.
