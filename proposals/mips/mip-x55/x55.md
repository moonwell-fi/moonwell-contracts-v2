# MIP-X55: Enable xWELL Bridging on Ethereum Mainnet

## Summary

This proposal enables `xWELL` bridging between Ethereum mainnet and the existing
Moonwell deployments on Moonbeam, Base, and Optimism. It registers each remote
`WormholeBridgeAdapter` as a trusted sender on the Ethereum adapter and sets the
matching outbound target addresses, completing the Wormhole bridge mesh for
`xWELL`.

This is a setup proposal that must execute **before MIP-X56** (the
`MultichainGovernorV2` migration to Ethereum). At the time MIP-X55 is executed,
Ethereum governance is not yet live, so the calls are submitted directly by the
Moonwell **Foundation Multisig**.

## Motivation

`xWELL` is already deployed on Ethereum mainnet (proxy:
`0xA88594D404727625A9437C3f886C7643872296AE`) with its `WormholeBridgeAdapter`
at `0x734AbBCe07679C9A6B4Fe3bC16325e028fA6DbB7`, but the adapter has no remote
peers configured. As a result, no `xWELL` can move between Ethereum and the
other chains.

MIP-X56 will migrate governance to Ethereum and rely on `xWELL` voting power
sourced from all four chains. The bridge mesh must be live before that migration
so token holders can already hold and move `xWELL` on Ethereum when governance
flips.

## Prerequisites

The Ethereum `xWELL_PROXY` and `WORMHOLE_BRIDGE_ADAPTER_PROXY` are currently
owned by `MOONWELL_DEPLOYER` (`0xdDbf679d6332d9E5b409865b9671d1927255B52A`).
Before this proposal can be executed:

1. `MOONWELL_DEPLOYER` runs `script/TransferEthereumXWellOwnership.s.sol`, which
   calls `transferOwnership(FOUNDATION_MULTISIG)` on both contracts.
2. `FOUNDATION_MULTISIG` (`0x74Cbb1E8B68dDD13B28684ECA202a351afD45EAa`) submits
   two Safe transactions calling `acceptOwnership()` on `xWELL_PROXY` and
   `WORMHOLE_BRIDGE_ADAPTER_PROXY` (both contracts use OpenZeppelin
   `Ownable2Step`).

> **Verify:** confirm `0x74Cbb1E8B68dDD13B28684ECA202a351afD45EAa` is the
> canonical Moonwell Foundation Safe on Ethereum mainnet (matches the address
> already registered on Base). If a different Safe is desired, update
> `chains/1.json#FOUNDATION_MULTISIG` and re-run the calldata generation.

## Specification

The proposal builds two batched calls against the Ethereum
`WORMHOLE_BRIDGE_ADAPTER_PROXY`:

### Peers (`TrustedSender[]`)

| Chain    | Wormhole Chain ID | Adapter Address                              |
| -------- | ----------------- | -------------------------------------------- |
| Moonbeam | 16                | `0x734AbBCe07679C9A6B4Fe3bC16325e028fA6DbB7` |
| Base     | 30                | `0x734AbBCe07679C9A6B4Fe3bC16325e028fA6DbB7` |
| Optimism | 24                | `0x734AbBCe07679C9A6B4Fe3bC16325e028fA6DbB7` |

(All `WormholeBridgeAdapter` deployments share the same CREATE2 address across
chains.)

### Calls

1. `addTrustedSenders((uint16,address)[])` with the three peers above —
   whitelists inbound VAAs from Moonbeam/Base/Optimism, allowing `xWELL` to be
   minted on Ethereum when a bridge-in VAA is delivered.
2. `setTargetAddresses((uint16,address)[])` with the same three peers — sets the
   outbound destination address for each chain so that
   `WormholeBridgeAdapter.bridge(dstChainId, amount, to)` from Ethereum lands at
   the correct peer on the destination chain.

Both calls are required. `addTrustedSenders` alone leaves the bridge inbound
only; `setTargetAddresses` alone leaves outbound traffic dispatched to an empty
address and bridge-out reverts.

### Out-of-Scope (handled elsewhere)

The reciprocal direction — Moonbeam/Base/Optimism adapters trusting and
targeting Ethereum — is not part of this proposal. Those changes are owned by
the Moonbeam `MultichainGovernor` and are handled as part of the
governance-migration bundle in MIP-X56.

## Execution

```sh
forge script proposals/mips/mip-x55/mip-x55.sol:mipx55 \
  --rpc-url ethereum -vvv
```

With `DO_BUILD=true DO_RUN=true DO_VALIDATE=true DO_PRINT=true`, the script
simulates the multisig executing the calls, asserts the trusted-sender and
target-address mappings are populated for all three peers, and prints the
calldata to be copied into the Foundation Safe.

## Security

- Both functions (`addTrustedSenders`, `setTargetAddresses`) are
  `onlyOwner`-guarded on `WormholeBridgeAdapter`; the multisig is the sole
  caller.
- `addTrustedSenders` uses `EnumerableSet.add` which reverts on duplicate
  entries — first-time wiring only; safe re-runs require `removeTrustedSenders`
  first.
- No upgrades, no token movement, no rate-limit changes. Mint/burn limits on
  Ethereum `xWELL` remain at their post-deployment defaults until
  governance-driven adjustments land.
