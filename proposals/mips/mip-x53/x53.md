# MIP-X53: Fix Chainlink OEV Loan-Feed Desync (Full-Coverage Redeploy)

## Summary

Redeploys every Core `ChainlinkOEVWrapper` enumerated in
`ChainlinkOracleConfigs._oracleConfigs` on Base and Optimism so the loan-feed
dereferencing fix is baked into the new bytecode, then re-wires
`ChainlinkOracle.setFeed(symbol, newWrapper)` for every market that consumed the
old wrapper. On Base, the `ChainlinkOEVMorphoWrapper` proxy implementation is
also upgraded to restore round-data validation parity with the Core wrapper.

Each redeployed wrapper preserves the existing wrapper's full configuration read
live from on-chain state (`priceFeed`, `chainlinkOracle`, `feeRecipient`,
`owner`, `liquidatorFeeBps`, `maxRoundDelay`, `maxDecrements`), so the only
observable change post-upgrade is the loan-feed dereferencing logic.

The fix dereferences any OEV wrapper registered under the loan token's symbol
down to its raw Chainlink aggregator before reading `latestRoundData()`, so the
liquidation fee split uses the same freshness reference on both sides. The
Morpho wrapper change additionally restores validation parity with the Core
wrapper: `updatedAt != 0` and `answeredInRound >= roundId` are now enforced on
the loan feed.

## Impact

Medium-severity finding acknowledged by the sponsor as a goodwill bounty. No
funds at risk. Affects only the liquidator/protocol fee split accuracy during
OEV liquidations.

## Actions

### Base

For every `oracleName` enumerated in `ChainlinkOracleConfigs._oracleConfigs`
(Base) that resolves to a live OEV wrapper:

- Archive the existing wrapper address under
  `<oracleName>_OEV_WRAPPER_DEPRECATED_V3` (the X43-era wrapper being retired).
- Deploy a new `ChainlinkOEVWrapper` mirroring the existing wrapper's on-chain
  parameters exactly and register it under the canonical
  `<oracleName>_OEV_WRAPPER`.
- `ChainlinkOracle.setFeed(symbol, newWrapper)` for every symbol mapped to that
  `oracleName` (e.g. `CHAINLINK_USDC_USD` covers both `USDC` and `USDbC`).

Covered Base feeds: `DAI_ORACLE`, `CHAINLINK_USDC_USD`,
`CHAINLINK_ETH_USD_FEED`, `CHAINLINK_AERO_ORACLE`, `CHAINLINK_BTC_USD`,
`CHAINLINK_EURC_USD`, `CHAINLINK_WELL_USD`, `CHAINLINK_USDS_USD`,
`CHAINLINK_TBTC_USD`, `CHAINLINK_VIRTUAL_USD`, `CHAINLINK_MORPHO_USD`,
`CHAINLINK_cbXRP_USD`, `CHAINLINK_MAMO_USD`, `CHAINLINK_VVV_USD`.

Composite-wrapped feeds (`_compositeOracleConfigs`) are intentionally left
untouched.

Additionally:

- Upgrade `ChainlinkOEVMorphoWrapper` proxy implementation. No `reinitializer` —
  storage layout unchanged.

### Optimism

For every `oracleName` enumerated in `ChainlinkOracleConfigs._oracleConfigs`
(Optimism) that resolves to a live OEV wrapper:

- Archive the existing wrapper address under
  `<oracleName>_OEV_WRAPPER_DEPRECATED_V3` (the X43-era wrapper being retired).
- Deploy a new `ChainlinkOEVWrapper` mirroring the existing wrapper's on-chain
  parameters exactly and register it under the canonical
  `<oracleName>_OEV_WRAPPER`.
- `ChainlinkOracle.setFeed(symbol, newWrapper)` for every symbol mapped to that
  `oracleName` (e.g. `CHAINLINK_USDT_USD` covers both `USDT` and `USD₮0`).

Covered Optimism feeds: `CHAINLINK_USDC_USD`, `CHAINLINK_USDT_USD`,
`CHAINLINK_DAI_USD`, `CHAINLINK_ETH_USD_FEED`, `CHAINLINK_WBTC_USD`,
`CHAINLINK_OP_USD`, `CHAINLINK_VELO_USD`.

## Parameters preserved

Per-wrapper parameters are read from on-chain state at deploy time and mirrored
on the redeployed wrapper. At the time of writing every wrapper on Base and
Optimism is configured with `liquidatorFeeBps=3000`, `maxRoundDelay=10`,
`maxDecrements=10` (set by MIP-X43), but the proposal does not assume this —
each new wrapper inherits whatever parameters its predecessor held.
