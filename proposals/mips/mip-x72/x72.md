# MIP-X72: Scope OEV Fresh-Round Unlock to the Paying Liquidation

## Summary

This proposal refreshes Moonwell’s Chainlink OEV oracle wrappers on Ethereum,
Base, and Optimism to close a gap in how the protocol captures Oracle
Extractable Value (OEV) from liquidations.

Moonwell uses OEV-aware oracle wrappers to delay the propagation of a fresh
Chainlink price round for a short window, during which liquidators can pay the
protocol for early access by routing their liquidation through the wrapper and
sharing the realized value. The current wrapper logic unlocks the fresh price
globally — for every ordinary oracle consumer — as soon as the first
wrapper-mediated liquidation occurs. This proposal updates the wrapper logic so
that the fresh-round unlock is scoped to the individual liquidation that paid
for it, and is not persisted for unrelated liquidations.

The proposal does not change interest rates, collateral factors, liquidation
thresholds, the configured fee split, or the underlying assets supported by
Moonwell. It is a technical fix designed to ensure the protocol’s OEV fee policy
is captured as intended. It does narrow which positions can be liquidated early
during the short round-delay window; that trade-off is described under
Liquidation Liveness Trade-off below.

## Background

OEV refers to value that can arise when liquidations depend on oracle price
updates. Moonwell’s OEV system is designed to let liquidators update prices
early and perform liquidations while sharing the realized value with the
protocol, currently under a 70/30 split (70% to the protocol, 30% to the
liquidator).

To make this work, the wrapper holds back a freshly published Chainlink round
for a maximum round-delay window. During that window, ordinary oracle consumers
continue to see the previous price, while a liquidator can pay for early access
to the fresh price through the wrapper’s `updatePriceEarlyAndLiquidate` path.

The issue is that the size of the protocol’s compensation is tied to the
liquidation the attacker chooses to route through the wrapper, while the
fresh-round unlock applies globally. In the current logic, the wrapper persists
the newly unlocked round to its shared cache after a wrapper-mediated
liquidation:

1. A fresh Chainlink round arrives during the delay window. Ordinary consumers
   still see the previous price.
2. An actor performs one small, valid liquidation through the wrapper’s OEV
   path. The protocol receives its fee split — but only on that small
   liquidation.
3. As a side effect, the wrapper advances its shared cached round to the fresh
   round.
4. The fresh price is now visible to every ordinary oracle consumer, including
   the standard `liquidateBorrow` path that does not route through the wrapper.
5. The actor then performs large follow-on liquidations through the ordinary
   path, using the fresh price but bypassing the OEV fee split entirely.

The result is foregone protocol OEV revenue: a tiny liquidation can pay to
unlock the fresh round market-wide, while the larger, more profitable
liquidations that follow avoid the protocol’s intended share. User funds and
protocol principal are not at risk — borrowers are still liquidated at the
correct fresh price — but the protocol does not collect the OEV revenue it was
designed to capture on the follow-on legs.

This finding is distinct from the previously addressed Halborn HAL-01 and 7.9
items: it does not rely on gas-price or fee-formula details, and it uses a
genuinely new round, so a “round must strictly increase” guard would not prevent
it.

## Proposal

This proposal updates the OEV oracle wrapper logic so that the fresh-round
unlock is scoped to the paying liquidation rather than persisted globally.

Specifically, the wrapper logic is changed to snapshot its cached round before
the nested liquidation reads the fresh price, and to restore that prior cached
round once the liquidation completes. The paying liquidation still executes
against the fresh price, but ordinary oracle consumers continue to see the
delayed price for the remainder of the round-delay window. Any subsequent
liquidator that wants the fresh price must again pay for it through the
wrapper’s OEV path.

To deliver this fix across all affected deployments, this proposal will:

1. Redeploy every live Core `ChainlinkOEVWrapper` listed in Moonwell’s Chainlink
   oracle configurations on Ethereum, Base, and Optimism, with the corrected
   logic.

2. Preserve each existing wrapper’s configuration exactly, mirroring the live
   on-chain values for:

   - Price feed
   - Chainlink oracle
   - Fee recipient
   - Owner
   - Liquidator fee basis points
   - Maximum round delay
   - Maximum decrements

3. Repoint each market’s `ChainlinkOracle` feed at its corresponding redeployed
   wrapper, so the corrected logic takes effect without changing the reported
   price.

4. On Base, upgrade the `ChainlinkOEVMorphoWrapper` implementation in place
   behind its existing proxies. Because the fix is logic-only, no
   re-initialization is required and all proxy storage is preserved.

5. Archive the existing wrapper addresses and implementation under deprecated
   names and register the refreshed wrappers under the canonical OEV wrapper
   names.

## Liquidation Liveness Trade-off

Scoping the unlock to the paying liquidation has a liveness cost that voters
should weigh.

The early unlock is per wrapper and per call. A wrapper-mediated liquidation
sees the fresh price only for the one feed whose wrapper it runs through, and
each wrapper only accepts liquidations that seize its own asset as collateral.
Any other OEV-wrapped feed with a new round still inside its delay window keeps
reporting the delayed price for the whole call. A position whose shortfall only
appears once a second OEV-wrapped feed is fresh therefore cannot be liquidated
early through any single wrapper call. Two examples:

- A borrower holding both WETH and cbBTC collateral after both prices fall.
  Liquidating through the ETH wrapper freshens ETH, but cbBTC still reports its
  stale, higher price, so the account can still appear healthy.
- A WETH borrow that goes underwater because the price of ETH rose. The ETH
  wrapper only accepts ETH as the seized collateral, so no wrapper call can
  freshen the price of the borrowed asset for a position collateralized in
  something else.

These positions wait until the relevant fresh round is older than that feed’s
maximum round delay. From then on every consumer sees the fresh price and
ordinary liquidation proceeds at that price, without OEV capture. Bad debt can
in principle build up during that wait, but only for the length of the delay.

Some context on the size and origin of this trade-off:

- It is not a new restriction for the first liquidation. Before this fix, the
  first wrapper-mediated liquidation also saw only its own wrapper’s fresh
  price. The only way to freshen a second feed inside the delay window was to
  run a separate small liquidation through that feed’s wrapper and let it unlock
  the round for everyone, which is exactly the behavior this proposal removes.
- The exposure is bounded by the maximum round delay. Read on-chain on 16
  October 2026, every live Core OEV wrapper on Ethereum, Base, and Optimism, and
  every Base Morpho OEV wrapper, is configured with a maximum round delay of 10
  seconds. On Base and Optimism, with blocks roughly every two seconds, that is
  about five blocks. On Ethereum, with twelve-second blocks, the next block is
  already past the window, so the delay only applies within the block in which
  the new round is published. This proposal carries those values over unchanged.
- The maximum round delay is a governance-owned setting on every wrapper. If the
  DAO later prefers faster liquidation of multi-feed positions over OEV capture,
  it can adjust the setting (it must remain above zero) without a code change.

## Rationale

Moonwell’s OEV system exists to capture value for the protocol from liquidations
that depend on fresh oracle prices. The DAO has already chosen a 70/30 OEV fee
split. This proposal does not change that policy; it ensures the policy is
actually enforced by preventing a single small liquidation from unlocking fresh
prices for unrelated liquidations that pay nothing to the protocol.

The refreshed wrappers are price-neutral by construction: each new Core wrapper
is reseeded to the latest round and forwards the same underlying aggregator, and
the Morpho wrapper upgrade preserves all existing storage. Simulation checks, on
every chain, that each refreshed Core wrapper forwards the same raw aggregator
round as the underlying feed and that reported prices stay within two percent of
a snapshot taken before execution. The tolerance allows for new oracle rounds
that land while the simulation runs against live network state.

## Voting Options

- **For:** Redeploy the Core Chainlink OEV wrappers on Ethereum, Base, and
  Optimism, upgrade the Base Morpho OEV wrapper implementation, and scope the
  fresh-round unlock to the paying liquidation.
- **Against:** Do not redeploy the Chainlink OEV wrappers or upgrade the Base
  Morpho OEV wrapper implementation.
- **Abstain:** Participate in governance without voting for or against the
  proposal.
